从零到一：用 Clash 打造专属电脑热点，让网络分享更智能、更自由

在当今这个万物互联的时代，网络早已不再是奢侈品，而是像空气与水一样渗透进我们生活的每一个缝隙。无论是远程办公、在线学习，还是追剧、打游戏，稳定且高效的网络连接都是刚需。然而，当我们身处酒店、会议室、临时办公点，或是家中宽带突然“罢工”时，如何让身边的手机、平板、甚至朋友的电脑也能顺畅上网，就成了一个令人头疼的问题。更别提，在某些网络环境下，我们还需要借助代理工具才能访问特定资源。这时候，如果你拥有一台安装了 Clash 的电脑，一切难题都将迎刃而解——它不仅能帮你科学上网，更能化身为一座智能的“网络灯塔”，将你的连接能力分享给周围所有设备。

为什么是 Clash？——不止于代理，更是网络中枢

很多人第一次接触 Clash，是因为它强大的代理功能。但如果你仅仅把它看作一个“翻墙工具”，那可就大材小用了。Clash 本质上是一个基于规则的网络流量管理引擎，它能够精细地控制进出你电脑的每一个数据包。正是这种底层的控制能力，让它成为开启电脑热点的绝佳搭档。

与 Windows 系统自带的“移动热点”功能相比，Clash 开热点有着无可比拟的优势：

  • 智能分流，各取所需：系统自带热点只是简单地把你的网络“广播”出去，所有设备都走同一条路。而 Clash 可以设定规则——比如让连接到热点的设备自动走代理访问国际网站，而国内流量则直连，互不干扰，速度与安全兼得。
  • 突破限制，共享代理：在某些受限网络中（如公司内网、校园网），系统可能禁止开启热点。但通过 Clash 的虚拟网卡和路由表操作，你可以巧妙绕过这些限制，将代理后的网络共享出去。
  • 流量可视化与管控：Clash 提供了详尽的连接日志和流量统计，你可以实时看到哪些设备在消耗流量，甚至可以通过规则阻止特定设备访问特定网站，这对于家长控制或临时访客网络来说，简直是一把“瑞士军刀”。

简单来说，Clash 让“开热点”这件事从“物理层面的共享”升级为“逻辑层面的智能分发”。你不再只是一个网络的中转站，而是一个可以自定义游戏规则的“网络运营商”。

实战演练：Windows 系统下用 Clash 开启热点的完整指南

下面，我将以最常用的 Windows 操作系统为例，手把手带你走一遍全流程。请确保你已经在电脑上安装好了 Clash（无论是 Clash for Windows 还是 Clash Verge 等内核一致的客户端均可），并且你的代理订阅或节点配置已经生效，能够正常访问外网。

第一步：准备工作——让 Clash 允许局域网连接

这是最关键的一步，也是 90% 新手最容易忽略的步骤。默认情况下，Clash 只监听本机（127.0.0.1）的流量，这意味着其他设备根本无法通过你的电脑上网。

  1. 打开你的 Clash 客户端，找到“设置”或“General”选项。
  2. 寻找 “允许局域网连接” （Allow LAN）或 “允许来自局域网的连接” 的开关，将其打开。
  3. 此时，Clash 会提示你防火墙需要放行。请务必点击“允许”或“同意”，否则外部设备依然会被 Windows 防火墙拦截。

打开这个开关后，你的 Clash 就从一个“私人管家”变成了“公共服务员”，它会在局域网内开放一个代理端口（通常是 7890）。

第二步：启用 Windows 自带的移动热点

虽然我们要用 Clash 来接管网络，但物理层的无线信号发射还是需要借助 Windows 的“移动热点”功能。

  1. 点击任务栏右下角的网络图标，打开“移动热点”设置（或者直接在设置中搜索“移动热点”）。
  2. 将“与其他设备共享我的 Internet 连接”开关打开。
  3. 在下方设置一个你喜欢的网络名称（SSID） 和网络密码。密码建议设置 8 位以上混合字符，防止隔壁老王蹭网。

此时，Windows 会自动创建一个虚拟 Wi-Fi 网卡。但请注意，现在这个热点还没有“网”可上，因为它默认使用的是你电脑当前正在使用的物理网卡（比如以太网或 Wi-Fi），而这条链路并没有经过 Clash 处理。

第三步：关键桥梁——修改“Internet 连接共享（ICS）”

这是整个设置中最容易让人困惑的一步。我们需要把“移动热点”的虚拟网卡，指向 Clash 创建的虚拟网卡（通常是 TUN 模式下的网卡，或者 Clash 监听的那个回环地址）。

这里有两种主流方案，我推荐你使用第一种：

方案 A：利用 Clash 的 TUN 模式（虚拟网卡模式）

  1. 在 Clash 客户端中，开启 TUN 模式（或称为虚拟网卡模式）。开启后，你的电脑上会出现一个名为 “Meta” 或 “TUN” 的虚拟网卡。
  2. 此时，Clash 已经接管了本机所有流量。但为了让热点设备也走 TUN，我们需要修改 ICS 服务。
  3. 按下 Win + R，输入 ncpa.cpl 打开网络连接窗口。
  4. 找到“本地连接* 2”（或类似名字的虚拟网卡，通常对应移动热点），右键点击它，选择“属性”。
  5. 切换到“共享”选项卡。
  6. 勾选“允许其他网络用户通过此计算机的 Internet 连接来连接”。
  7. 在下拉框中，选择 你开启的 TUN 虚拟网卡（注意，不是你的物理网卡，而是 Clash 创建的那个）。
  8. 点击确定。

方案 B：手动指定代理（适合没有 TUN 模式的老版本）

如果你不想用 TUN 模式，那么需要在连接热点的设备上手动设置代理。

  1. 在移动热点的“属性”中，找到“Internet 连接共享”，选择你的物理网卡（比如以太网）。
  2. 连接上这个热点的手机或平板，在 Wi-Fi 设置中，开启“手动代理”。
  3. 服务器地址填写你电脑的局域网 IP（例如 192.168.137.1，这是 Windows 热点的默认网关），端口填写 Clash 的代理端口（默认 7890）。

这种方法虽然可行，但每次连接新设备都需要手动配置，比较繁琐。因此，强烈建议你使用 TUN 模式 + ICS 共享，这样连上热点的设备就无需任何设置，自动获得“智能代理”能力。

第四步：验证与调试——确保一切顺畅

完成上述设置后，请按以下顺序检查：

  1. 查看 Clash 日志：在 Clash 的“日志”界面，你应该能看到来自其他设备 IP 的连接请求。
  2. 在手机上进行测试：用手机连接你设置的热点，打开浏览器访问一个国内网站（如百度），应能正常打开。接着，尝试访问一个需要代理才能访问的国外网站（如 YouTube 或 Google），如果也能打开，说明代理分流生效了。
  3. 检查 DNS 问题：如果网页能打开但图片加载慢，或者某些 App 无法连接，可能是 DNS 污染问题。此时，你需要在 Clash 的 DNS 设置中，启用“Fake-IP”模式或指定公共 DNS（如 8.8.8.8），并确保 DHCP 给热点设备分配的 DNS 也是 Clash 的虚拟网关地址。

进阶玩法：让热点更智能、更安全

既然你已经成功通过 Clash 开启了热点，为什么不更进一步，把它打造成一个真正的高级网络节点呢？

1. 精细化的规则分流

在 Clash 的配置文件中，你可以编辑 rules 部分。例如，你可以制定这样一条规则：凡是连接到这个热点的设备，访问 Netflix 和 YouTube 时走美国节点，访问 Spotify 时走新加坡节点，而访问国内视频网站时则直接直连。这样，无论你的朋友用热点看什么，都能获得最佳的体验，且不会占用你过多的国际带宽。

2. 基于设备的限速与隔离

虽然 Clash 本身不带限速功能，但你可以结合 Windows 的 QoS 策略，或者使用 Clash 的 profile 模板配合第三方插件（如 TUN 模式下的流量控制脚本），对特定 MAC 地址或 IP 段进行带宽限制。这对于防止某个设备疯狂下载导致热点卡顿非常有效。

3. 安全加固

  • 修改默认端口：在 Clash 配置中，把代理端口从默认的 7890 改为一个不常用的高位端口，可以避免被局域网内的恶意扫描。
  • 开启防火墙规则：在 Windows 防火墙中，只允许来自热点网段（192.168.137.0/24）的流量访问 Clash 端口，其他外部请求一律拒绝。
  • 定期更换热点密码：既然你共享的是经过代理的网络，密码设置得复杂一些，能有效防止被“白嫖”流量，同时也保护了你的代理节点不被滥用。

常见问题与故障排查（FAQ 深度解析）

在实际操作中，你可能会遇到以下问题，别急，我们逐一击破：

问题一：手机能连上热点，但网页打不开，且 Clash 日志无任何记录。 解决方案：这通常是 ICS 共享选错了网卡。请回到 ncpa.cpl，右键点击移动热点对应的虚拟网卡（通常是“本地连接* 10”之类的），在共享选项卡中，确认下拉框选的是 Clash 的 TUN 网卡，而不是你的 Wi-Fi 或以太网卡。

问题二：热点能上网，但所有流量都直连，没有走代理。 解决方案：这是因为 Clash 的 TUN 模式没有捕获来自 ICS 的流量。请检查 Clash 设置中的“路由设置”，确保“TUN 模式”下的“堆栈”选择为“混合”或“GVisor”，并勾选“自动路由所有流量”。同时，确保 Clash 的系统代理是关闭状态，否则可能会引起回环冲突。

问题三：连接热点的设备无法访问局域网内其他设备（如打印机）。 解决方案：Clash 的 TUN 模式默认会拦截所有流量。你需要在 Clash 的配置文件中添加一条规则：IP-CIDR,192.168.137.0/24,DIRECT，让局域网流量直连，不经过代理。

问题四：Clash 内核崩溃或 CPU 占用过高。 解决方案：这可能是因为开启了 TUN 模式后，与 Windows 的 Hyper-V 或 WSL2 冲突。尝试在 Clash 的 TUN 设置中，将“网卡类型”从“TUN”改为“Wintun”，或者关闭 Windows 的“网络连接共享”中的“允许其他网络用户控制”选项。
